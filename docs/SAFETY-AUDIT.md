# 0.3.6 安全审计

日期：2026-11-08（Asia/Shanghai）。范围：插件 `src`、所使用的引擎与 TrueHUD 接口、Hook ABI，以及本次新增缓存和配置发布。

## 独立审核结果

Luna（xhigh）以只读方式独立检查 `src` 中全部 28 个 C++ 源码/头文件、TrueHUD 接口，并核对相关 CommonLib 库存、设置和句柄实现。审核确认的超限注释重复解析问题已修复，子代理已复核关闭；在所检查的普通运行路径中，没有剩余的确证缺陷。该结论以以下引擎生命周期及线程契约为边界。

## 已落实的修复

| 方面 | 访问路径与处理 |
| --- | --- |
| 配置并发 | 原菜单回调直接修改共享容器。现在构造新的 `Configuration`，完成后原子发布 `shared_ptr<const Configuration>`；读者持有同一快照直至计算结束，避免容器重分配使读者迭代器失效。菜单更新通过 SKSE 主线程任务执行。 |
| 动画图访问 | 持有 `BSAnimationGraphManagerPtr` 后，用 `GetRuntimeData().updateLock` 保护 graphs、behaviorGraph、activeNodes、clip 和 annotation 遍历；使用 NG 的 SE / AE 布局访问器。 |
| 角色寿命 | 武器命中保留句柄解析得到的 `NiPointer`；魔法处理和当前 HUD 回调也在调用期间保持角色引用。没有把角色、效果或动画指针放进持久缓存。 |
| 空指针 | 检查 HitData、ActorBase、装备条目、图管理器、首张图、行为图、节点、clip、binding、animation、track、注释文本和 RTTI 名称。HUD 检查 API、角色与正总韧性后再计算比例。 |
| API 发布 | TrueHUD 接口指针改为原子发布，每个调用使用一次加载的局部指针；游戏设置绑定也以原子指针保存。 |
| 异常边界 | 配置重载捕获 `std::exception` 并保留上一个完整快照；无效注释捕获 JSON 异常并缓存失败结果。 |
| 注释资源预算 | 独立子代理发现超长文本原本绕过缓存、每次在动画锁内重新解析。现在超过 1 MiB 的单条 JSON 在查表、解析和分配缓存键之前拒绝；回归检查重复输入的解析次数为零。 |

动画锁范围内没有 Perk 分发、脚本调用或 HUD 调用。`BSSpinLock` 的本地实现支持同线程递归获取；没有另加一把锁与引擎更新锁竞争保护同一份数据。

## 内存与堆栈

配置使用 RAII 所有权；旧快照由最后一个读者释放。注释缓存拥有字符串和普通值，最大 512 条、1 MiB 键文本/线程，预算不包含容器管理开销；线程退出时析构。没有跨帧缓存借用的游戏容器、临时字符串或动画地址。

插件代码没有新增递归、`alloca` 或由外部长度决定的栈数组；大容器位于堆上。Hook 继续使用已核查的 Windows x64 ABI 和 56 字节 trampoline。DLL 的 PE 检查确认 ASLR、DEP 与安全 cookie 均存在，见 [audit/plugin.json](audit/plugin.json)。这些编译保护不验证引擎传入对象的有效性。

独立堆栈复核未发现递归调用链、可变长栈分配或 Hook 参数声明错配；两个 `GetAnimImmuneLevel` 重载不是相互递归。`CPrint` 的 `va_start` / `va_end` 配对，当前两个调用点仅生成固定文本和数值，没有确认的格式串缺陷。独立代理只核对源码签名，没有重新反汇编游戏；之前的调用点、虚表槽位和寄存器核查见 [NG-MIGRATION.md](NG-MIGRATION.md) 及其中两版游戏的二进制报告。第三方库内部栈深和实际游戏调用栈没有通过本次静态审核证明。

## 引擎契约边界

- `NiPointer` 保持已经有效对象的引用计数寿命；它不能修复调用方传入的悬空地址，也不锁住角色内部状态。
- 原生命中/更新 Hook 仍在游戏调用线程执行。本次没有将游戏访问移到工作线程，也没有宣布所有引擎接口都能从任意线程调用。
- CommonLib 的 `MagicTarget` 明确说明 SE / AE 的活动效果遍历不加锁，`ActiveEffect` 也不受引用计数保护。这里仅同步借用列表与效果，跳过空项，不跨回调保存，不在遍历中调用脚本或 Perk；效果列表的有效性仍依赖游戏执行阶段。改用 `VisitActiveEffects` 本身无法提供缺失的锁。
- 缓存的 `RE::Setting*` 和关键字依赖加载后对象地址稳定。设置数值仍实时读取，原子绑定不等于同步引擎对设置内容的并发修改。
- TrueHUD 头文件没有提供任意线程调用或动态卸载保证。API 指针的原子访问只保护插件自己的发布；仍依赖 TrueHUD 模块在回调期间保持加载，以及其回调提供有效角色。
- 独立审核指出 TrueHUD 接口定义了线程 ID 和 `BadThread`，但没有说明特殊资源回调的执行线程。库存快照构造仍遍历实时库存，需要实机确认回调与原生 Hook 所在线程允许这些访问。
- 预算内首次出现的 JSON 仍在动画锁内解析，冷缓存的大文本可能延长持锁时间；审核没有发现死锁的证据。
- JSON、缓存、库存快照等分配失败的 `std::bad_alloc` 仍可能沿原生 Hook 传播。配置重载有异常边界，其余路径没有通过宽泛捕获掩盖资源耗尽。

## 验证证据

NG Release 已完整编译。隔离回归覆盖 3000 组装备、5000 组恢复、注释/设置缓存；同一测试以 MSVC AddressSanitizer、异常展开和调试信息重新编译后通过，没有报告堆栈越界、堆越界或释放后访问。日志：[普通回归](audit/performance-checks.txt)、[ASan](audit/safety-checks-asan.txt)。

ASan 测试没有加载游戏、动画线程或 TrueHUD，也不是线程竞争检测器。实机加载/卸载角色、并发动画更新、活动效果变化、存档切换仍需游戏内验证。
